# 3. Projects

## 3.1 Layout

A WaSL project is a directory:

```
calc/
├── wasl.toml          # manifest: identity of the package
├── src/               # source files
│   ├── calc.wasl
│   └── util/
│       └── clamp.wasl
└── build/             # generated by `weasel build`
    └── calculator.wasm
```

- The **root** of the project is the directory that contains `wasl.toml` and `src/`.
- The tools operate on the project whose root is the **current directory** (§ 14.1). They do not search parent directories.

## 3.2 Manifest `wasl.toml`

The manifest is a [TOML](https://toml.io) file that declares the identity of the package.

```toml
[package]
namespace = "example"
name = "calc"
version = "0.1.0"
```

| Field | Required | Rule |
|---|---|---|
| `namespace` | yes | lowercase WIT identifier: words of ASCII lowercase letters and digits, separated by `-`, each word starting with a letter (e.g. `example`, `my-org`) |
| `name` | yes | same rule as `namespace` (e.g. `calc`, `todo-api`) |
| `version` | yes | SemVer version `MAJOR.MINOR.PATCH`, three decimal numbers without leading zeros (`0.1.0`, `1.12.3`), optionally followed by a pre-release (`-alpha.1`) or build (`+build.5`) suffix |

- The file contains exactly one table, `[package]`, with exactly these three fields. Any other table or field is an error.
- The identity of the WIT package is `namespace:name@version`, e.g. `example:calc@0.1.0`.
- An invalid manifest is reported with code E0200 (§ 11.4).

## 3.3 Source files

- Every file whose name ends with `.wasl` in `src/` or in any sub-directory of `src/` is a source file of the package. Other files are ignored.
- Source files are UTF-8 (§ 4.1).
- All the source files form **one package**: a declaration of any file is visible in every file.
- File and directory names have **no meaning** for the language. By convention, a file is named after the main interface or world it declares.
- The order of the declarations does not matter: a declaration can be used before it is declared, including from another file.
- Files are processed in a fixed order: sorted by the byte order of their path, written relative to the root with `/` separators (e.g. `src/a.wasl`, then `src/b.wasl`, then `src/b/c.wasl`). This order only decides which error is reported first (§ 11.2).
- In diagnostics, a file is designated by this relative path, e.g. `src/util/clamp.wasl`.

## 3.4 Outputs

- `weasel build <world>` writes the component of the world `<world>` to `build/<world>.wasm`, where `<world>` is the WaSL name of the world (`build/calculator.wasm`).
- Each world is built separately (§ 2.3): a project with three worlds produces three files, with three builds.
- `build/` only contains generated files; `weasel clean` removes it.
- A component is a standard WebAssembly component: it can be inspected with `wasm-tools`, run with wasmtime and composed with other components.
