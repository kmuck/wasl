# v2.11 Open questions

These questions were met while writing the target program and this draft. Each one has a default in the chapters above; this list says where the default is weakest.

1. **Error propagation.** `total` and `mark_paid` show how often a `result` is matched only to return its `err`. An operator such as `?` (§ 16.3) would remove most of these `match`es. It is left out of v0.2 so that `match` is designed first.
2. **Qualified constructors.** Every case is written with its type (`status::paid`, `option::some(x)`, `result::ok(sum)`), even where the expected type already determines it. This keeps one way to write each value and makes code readable out of context, at the cost of length. The alternative is bare cases where a type is expected (`return paid;`).
3. **Field order in record literals.** v0.2 requires declaration order (§ v2.4.4). It is easy to relax later and impossible to tighten, which is why the strict rule comes first.
4. **Equality of heap values.** `==` only applies to strings and enums. Structural equality for records, lists, options and results is convenient but hides a deep traversal; identity equality (`ref.eq`) exposes something the boundary does not preserve (§ v2.5.4). Neither is in v0.2.
5. **`list<T>` as a read-only view.** Lists are always mutable Wasm arrays (§ v2.6.1), and `list<mut T>` is usable as `list<T>` without a copy (§ v2.2.6). The alternative is a real immutable list, which would cost a copy every time a list built in a loop is returned.
6. **Where types are declared.** Types live in interfaces, as in WIT, and a function may use the types of any interface. Interfaces that only hold shared types become types-only interfaces in WIT (§ v2.7.1). Whether wit-component accepts every such world, in particular one that exports both the types interface and the interface that uses it, must be checked by the implementation.
7. **Text formatting.** `text::from_u32` in the target program is the kind of function every project needs. It belongs to the standard library (chapter 16), which does not exist yet; until then, projects write their own.
8. **The `gc` option of the Canonical ABI.** When runtimes let WasmGC references cross component boundaries, the adapters of chapter v2.7 disappear, and so do the copies of § v2.5.4. Two programs could then behave differently if one relies on receiving a private copy (as `mark_paid` does). The language should decide now whether arguments of exported functions are guaranteed to be private copies, or only *may* be.
9. **`char`, `tuple` and `flags`.** They are WIT types that v0.2 leaves out. They are needed to implement some foreign interfaces.
10. **Keywords.** `match` and `case` become keywords (§ v2.1.3). `switch` / `when` or `=>` arms were considered; `case … { }` was kept because it reuses the block syntax of `if`.
